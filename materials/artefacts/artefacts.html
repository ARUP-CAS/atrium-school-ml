The artefacts dataset

Where these photographs come from

  • A detectorist finds an object in a field
  • They report it — findspot, a photograph, sometimes a guess at what it is
  • An archaeologist checks the record and assigns a type from a controlled list
  • The photograph lands in AMČR-PAS, the public portal of the Archaeological Information System of the Czech Republic

Note

Every step in that chain is a filter. Hold on to that — it comes back in problem 1.

Three filters worth naming out loud if a question comes: what the detector beeps at, what a finder thinks is worth reporting, and what survives in the ground at all. Do not develop it here — it is the imbalance slide’s job.

AMČR-PAS: amcr-info.cz. Photographs are published under CC BY-NC 4.0 with a DOI per record.

This is a real working dataset, with all the untidiness that implies. We will open the actual file in a minute.

The 95 declared-but-unused categories are the most revealing number here. They come from the national thesaurus: the vocabulary was designed for the whole archaeological record, and this dataset only ever sees the part of it that a detectorist finds.

What “annotated” means

Four things people mean by it

Rosary: AMČR M-202400071-N00083, CC BY-NC 4.0

Same photograph, same objects. The annotation is a choice, and it is the expensive one.

Walk left to right, top to bottom, one sentence each. Then the question: which of the four do you need? The honest answer is almost always “one level less than you assumed”. The orange fields in panel 4 are deliberate — they are the ArchaeoTag hook, come back to them.

The task shape sets the bill

You want You annotate Roughly, per image
what is in this photograph? one label seconds
how many, and where? a box per object tens of seconds
what is its exact outline / area? a polygon per object minutes
what condition is it in? attributes per object seconds — if you decided the fields in advance

The order matters

Going from boxes to polygons after you have annotated 2 000 images means annotating 2 000 images again. Going the other way is free.

Yesterday: the task shape follows from the question. Today: and the question has a price.

This is the slide to slow down on. If they take one thing from the morning it is that the annotation schema is a commitment, not a setting, and it is made before anyone has trained anything.

COCO: four keys and a convention

{
  "info":        { ... },
  "licenses":    [ ... ],
  "images":      [ {"id": 1, "file_name": "...", "width": 3978, "height": 2762}, ... ],
  "categories":  [ {"id": 1, "name": "adornment"}, {"id": 63, "name": "fibula"}, ... ],
  "annotations": [ {"image_id": 1, "category_id": 63, "bbox": [...], "segmentation": [...]}, ... ]
}
  • One file for the whole dataset — images, label set and annotations together
  • annotations point at images and categories by id, so nothing is repeated
  • It carries boxes and polygons in the same record, which is why it is the default

Tip

Common Objects in Context — a benchmark dataset from 2014 whose file layout outlived it and became the de-facto interchange format.

Open the real file on screen now, not after the slide: categories first, then find the rosary in images, then filter annotations by its id. Let them watch you get lost for a second — that is the honest experience of a COCO file.

One annotation, as it really is

{
  "id": 1042,
  "image_id": 388,
  "category_id": 42,
  "bbox": [837.8, 1760.0, 485.2, 445.9],
  "area": 216350.7,
  "segmentation": [[1301.3, 1762.7, 1279.0,
                    1760.0, 1257.0, 1777.0, …]],
  "iscrowd": 0,
  "attributes": {"recognizable": "true",
                 "occluded": false}
}
  • bbox is x, y, width, height — corner, not centre
  • segmentation is one flat list: x1 y1 x2 y2 …, here 47 vertices
  • category_id is a number. The word cross lives only in categories
  • attributes is not standard COCO — the tool added it

Warning

Four of those fields are places where two tools disagree about what the numbers mean.

The attributes key is the important one: it is an extension, it round-trips through CVAT and Label Studio but not through most training code. That is the general lesson — the useful archaeological metadata is exactly the part the format does not standardise.

The same annotation, three formats

COCO · one file

"category_id": 42,
"bbox": [837.8, 1760.0,
         485.2, 445.9],
"segmentation": [[…]]

Corner, absolute pixels. Keeps the polygon.

YOLO · one .txt per image

2 0.271594 0.717940
  0.121971 0.161441

Centre, normalised 0–1. The class is an index — the word cross is not in the file.

Pascal VOC · one .xml per image

<object>
 <name>cross</name>
 <bndbox>
  <xmin>838</xmin>
  <ymin>1760</ymin>
  <xmax>1323</xmax>
  <ymax>2206</ymax>
 </bndbox>
</object>

Two corners, absolute. Keeps the name.

Important

Every conversion is lossy in a different direction. Export to YOLO and your polygons are gone; re-import and you cannot tell class 2 from class 20 without the original categories list.

If time is short, cut the VOC column and keep COCO vs YOLO — the normalisation and the lost class name are the two things worth their slide space.

Three tools

Label Studio

What it is for

  • Any data type, not only images — text, audio, time series
  • The label set is a small XML config, so the same project is reproducible
  • Multiple annotators on the same task out of the box
  • Exports COCO, YOLO, VOC and its own JSON

What we will do

  1. Look at the project you are about to work in
  2. Read its labelling config out loud — the classes and the three checkboxes
  3. Annotate one find, live
  4. Export it and open the JSON

The config is the schema. If you can read it, you know exactly what the dataset will contain.

Live. Keep it to five minutes: config, one annotation, one export. Resist the urge to tour the interface — they are about to use it themselves for sixteen minutes.

CVAT

What it does differently

  • Built for images and video only, and it shows — interpolation between frames, keyboard-driven polygon editing
  • Jobs and assignments: a 9 000-image task split across people, with review
  • Model-assisted annotation is a first-class feature, not a plug-in

When to choose which

mixed data, many small projects Label Studio
one large image corpus, a team, a deadline CVAT
you need SAM in the loop either — CVAT out of the box

Note

The AMČR-PAS annotations you have been looking at were made in CVAT — that is where recognizable and occluded come from.

Four minutes, and this is the first thing to cut if the clock is against you: show the job/review split and the fact that our own data came out of it, then move on.

Why a polygon hurts

Rosary: AMČR M-202400071-N00083, CC BY-NC 4.0

One photograph. At 10 749 annotations across the collection, that is the scale of what somebody already did by hand.

Let this one sit for a beat before saying anything. The dots do the argument. Then: this is why model-assisted annotation is not a luxury.

SAM 2: click instead of trace

  • A foundation model for segmentation — it has no idea what a fibula is, and does not need one
  • You give it a point, a box or a scribble; it returns a mask
  • It is class-agnostic: it finds the boundary, you supply the label
  • In CVAT and Label Studio it sits behind the polygon tool — one click, then you correct

Watch it fail

A corroded find on a background close to its own tone, and the mask leaks into the scale bar. Model-assisted is not model-decided — correcting a bad mask can cost more than drawing a good one.

Live: one clean find (instant, convincing), then deliberately a corroded one on the grey card. Show the mask leaking, fix it with a negative point, and say the honest number — assisted annotation is perhaps three to five times faster on easy objects and no faster at all on hard ones.

Where you disagreed

live Pull up the same photograph annotated by five different people.

  • The boxes will be close. Boxes usually are.
  • The classes will not, on two or three of the images — deliberately so
  • The attributes will be all over the place, because complete and corroded are judgements and nobody defined them for you

You have just produced, in sixteen minutes, the same disagreement that sits inside every archaeological dataset you will ever download.

Pick the two planted ambiguous images. Ask the people who disagreed to say why — out loud, without defending themselves. The answers are always about the definition, never about the photograph.

Agreement is a measurement

  • If two people disagree on 15% of images, no model trained on it can do better than 85% — the ceiling is in the data, not the architecture
  • Measure it: annotate an overlap set twice, report Cohen’s κ (two annotators) or Fleiss’ κ (more)
  • Where κ is low, the fix is not more annotators. It is a better definition, with pictures of the edge cases

Important

An annotation guide with worked examples of the hard cases is worth more than doubling your training set.

Do not teach the kappa formula. The claim that matters is the ceiling: it reframes “our model only gets 82%” from a modelling problem into a data problem, which is where it usually belongs.

Three problems

1 · What the ground gives you

Fibulae and coins are 40.1% of every annotation in the dataset.

Do not read the bars. One sentence: two classes out of a hundred and twelve hold two fifths of the data, and that is before you ask whether the other hundred are usable at all.

The tail is the dataset

  • 77 of the 112 types have fewer than 50 annotations — together, 8.9% of the data
  • 95 types are in the label set and have never been seen
  • A model trained on this learns 35 types well and the rest not at all

A classifier that ignores the image and always answers fibula scores 22%. Always fibula or coin: 40.1%.

The always-fibula baseline is the one number to make them write down. Any reported accuracy on an imbalanced set has to be compared against it, and a surprising number of published figures are not.

This is reporting bias, not the past

  • Metal detectors find metal — a fibula beeps, a potsherd does not
  • Finders report what looks like a find: complete, decorated, recognisable
  • Recorders assign the type they are confident about, and amorphous fragment when not
  • Archives digitise what is already catalogued

Important

40.1% fibulae and coins is a fact about detectorists, reporting and archives. It is not a fact about what was in the ground.

A model trained here learns the collection process at least as well as it learns the artefacts.

This is the intellectual centre of the session. Connect it back to the filter chain from the second slide of the deck — they have now seen the number the filters produce.

2 · Your labels are not their labels

You want to combine two datasets, or test a model trained on one against the other. Nothing lines up, and the places it does not are not obvious.

The identifiers behind these boxes need checking against the live vocabularies before this slide is shown — the terms are real, the mappings are the argument. See the prerequisites in the session plan.

SKOS, in three predicates

means safe to do
skos:exactMatch interchangeable in any context merge the two classes
skos:closeMatch interchangeable in some contexts merge, and say so in the paper
skos:broadMatch / narrowMatch one is wider than the other roll the narrow one up; never down
skos:relatedMatch associated, not substitutable do not merge

closeMatch does not chain

A closeMatch B and B closeMatch C says nothing about A and C. Two hops through a crosswalk and you have a class that means whatever the path happened to be.

SKOS is a W3C standard for publishing exactly this: concepts with stable URIs, their labels in several languages, and typed links between vocabularies.

exactMatch is transitive, closeMatch deliberately is not — that asymmetry is the whole practical content of the slide. If someone asks about OWL sameAs: SKOS is about concepts, not individuals, which is why it fits vocabularies and OWL does not.

What a crosswalk buys you

  • A shared coarse level — fibula, pin, buckle map cleanly; buckle/strap-end does not
  • Training on the union of two collections, honestly, with the merge written down
  • Evaluating a Czech-trained model on British data without silently renaming anything

The realistic outcome

You will lose resolution. Two datasets at 112 and 90 types may share 30 that map exactMatch. That is still a far better dataset than either alone — and the mapping is a research output in its own right.

Emphasise “written down”. The difference between a defensible merged dataset and a mess is a published mapping file, not the merging itself.

3 · The metadata nobody has time for

What the file records:

"attributes": {
  "recognizable": "true",
  "occluded": false
}

What you actually want:

"attributes": {
  "complete":  ?,
  "corroded":  ?,
  "has_scale": ?,
  "material":  ?,
  "view":      ?
}
  • Every one is a seconds-long judgement — and 10 749 × several seconds is weeks of somebody’s time
  • None of it needs a specialist. Anyone can see whether an object is broken or whether there is a ruler in the frame
  • Which makes it exactly the kind of work you can ask a crowd to do

Land the contrast: the polygons needed an expert and cost 677 clicks a photograph; these fields need no expertise at all and are the ones missing. That asymmetry is the argument for the next slide.

ArchaeoTag

Guess what this is

Phones out. Open the URL on the board — three minutes of play.

  • You are shown a photograph of a find and asked what it is
  • Along the way you answer the easy questions: complete? corroded? is there a scale?
  • You find out whether you were right — that is the game
  • We get a crowd-sourced answer to the fields the file does not have

Tip

The guessing is the incentive. The metadata is the point, and nobody playing has to care.

Three minutes of play, then stop them firmly — they will not want to stop. Have the results view ready on the projector before you start.

What a guess is worth

  • One guess is noise. Twenty guesses on the same photograph is a distribution
  • Where players agree, you have a usable attribute at effectively zero cost
  • Where they disagree, you have found a genuinely ambiguous object — which is worth knowing, and is exactly what you want an expert to look at
  • Their guesses at the class are a free baseline: how hard is this dataset for a human?

The same logic as the last hour: disagreement is data, not failure.

Warning

Crowd labels are good for is there a scale bar in this photograph. They are not good for is this an Almgren 236 fibula. Know which question you are asking.

Show the live results from the round they just played. If agreement on some attribute is poor, say so — it is the honest version of the same point they met in block 5.

Wrapping up

Five things to carry into the week

  1. The annotation schema is a commitment, not a setting — boxes to polygons means starting again
  2. Every format is lossy in its own direction; keep the COCO and export from it
  3. Disagreement between annotators is the ceiling on any model you train
  4. An imbalanced dataset describes how it was collected at least as much as what it contains
  5. Labels are local. Mapping between vocabularies is real work, and worth publishing
